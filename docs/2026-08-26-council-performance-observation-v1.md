# O Conselho — performance observation 1

Status: observation only; not promoted to a universal rule.

## What the first interpretation missed

The first pass softened carry-forward acceptance criteria and described the learning
requirement too narrowly. The second blind pass restored the full motion, responsive,
reversibility, scope-lock, and reporting obligations before implementation.

## Where intervention was needed

The work sequence needed an explicit correction: finish the requested official-source
research, reconcile it with the live code, freeze the contract, and only then implement.
No website code had changed before that correction.

## Finding that was not the real gap

The house timing was already usable. Retiming the entire house would have expanded scope.
The real defect was the banner presentation and the mismatch between responsive systems.

## Verification failure that looked like success

A source-string check protected a 56px opacity-derived translation even though the user
still saw a pop/fade. Page-load, canvas-presence, and overflow checks also did not measure
travel, semantic focus, collision, cropping, or reverse-scroll repeatability.

## Prompt structure that worked

Separate source wording from interpretation, then ask:

1. What was omitted?
2. What was softened?
3. What was added without authority?
4. What concrete failure could still pass the current tests?

Pair this questionnaire with official guidance and a read-only audit of the live routed chain.

## Reusable candidate

For responsive motion around a persistent visual stage: inventory breakpoint ownership,
align related breakpoints, lock semantic focus points, test forward and reverse coordinates,
and visually inspect focus-state collisions after numeric checks.

## Performance summary

Worked well: second blind pass, official-source review, locked scope, behavior-based checks,
and final visual inspection. Missed initially: carry-forward requirements and the weakness of
source-only verification. Improved: research changed the implementation boundary before
release, and visual evidence triggered the smallest allowed mobile fallback.

## Independent audit correction

The first completed package was correctly held. It used five separate fixed panels and five
perpetual measurement loops even though the frozen plan called for one rail. Offscreen links
also remained keyboard-focusable because pointer-event blocking does not remove an element
from tab order or the accessibility tree. A candidate fallback class also leaked into an
unrelated routed surface. These findings were fixed with one coordinator, one active card,
explicit accessibility state, and route-specific fallback composition.

Reusable audit addition: always test transformed-offscreen interactive elements with keyboard
tab order and assistive-technology state. Treat a performance architecture named in the frozen
contract—such as “one rail”—as an acceptance requirement, not an implementation suggestion.

## Portfolio launch confidence observation

Two blind seats initially agreed that six to seven V3 groups were strong enough for review.
That agreement was still incomplete: both relied on the generated export and visible sequence,
while the evidence seat reconciled exact filenames against the canonical Photo Catalog and found
phase, scope, and public-name conflicts. The Council correctly changed its answer instead of
averaging incompatible evidence.

Reusable rule: separate technical delivery, visual appeal, and documentary truth into distinct
scores, but let documentary conflicts act as hard gates. A beautiful photograph and two agreeing
reviewers cannot overrule a contradictory source of record. Require the evidence seat to inspect
the canonical catalog before unsealing visual or code opinions, then record why the stricter
source supersedes a provisional majority.

## Portfolio execution audit observation

The strongest audit sequence was: restore the historical dataset byte-for-byte, move the public
selection into a small launch-only dataset, derive the generated-output allowlist from that active
dataset, and verify both positive presence and negative absence. This made rollback and containment
measurable without deleting source evidence.

The visual audit also exposed a tooling trap: a stitched full-page screenshot appeared to duplicate
cards and footer regions even though the accessibility snapshot and DOM had exactly three articles
and one actual footer component. Viewport screenshots, element counts, bounding behavior, and direct
route checks resolved the false alarm. Reusable rule: never diagnose animated `whileInView` pages
from a stitched full-page capture alone; corroborate it with viewport captures and live DOM counts.

Final Council result: three independent seats returned VERIFIED. Evidence verified truth/privacy and
the 156-file allowlisted output; code review verified containment and legacy-route behavior; the
OpenAI-style reviewer verified build/test output and protected house/banner boundaries. The Council
did not vote to publish Production—it verified only that the exact isolated candidate is safe to put
on a separate review Preview.
